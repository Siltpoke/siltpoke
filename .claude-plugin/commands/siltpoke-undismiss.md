description: Reverse a previously dismissed review — flip status back to pending and undo its learned rule.
argument-hint: <critique-id>
---

You are reversing a Siltpoke dismissal at the user's explicit request.
The argument is the review id (e.g. `c-a7b3`) of a review that was
previously dismissed via `/siltpoke-dismiss`.

If `$ARGUMENTS` is empty, tell the user the usage is
`/siltpoke-undismiss <critique-id>` and stop. A review id is
required — there's no "latest" sugar yet (deferred).

Run:

```bash
bun ${CLAUDE_PLUGIN_ROOT}/src/cli/undismiss.ts $ARGUMENTS
```

What this does:

1. Flips the review's status from `dismissed` back to `pending` in
   its frontmatter file.
2. Looks up the dismissal in `feedback-archive.jsonl` and finds the
   learned rule (if any) that was generated by reflection.
3. Removes that learned rule from `memory.json` — **only when safe**:
   - Removed if the original dismissal **created** the rule (no other
     review relies on it).
   - Kept if the rule is shared (the original dismissal matched an
     existing rule that other dismissals also rely on).
4. Appends an audit entry to `feedback-archive.jsonl` with verdict
   `undismissed` so the timeline can be reconstructed.

Show the CLI output verbatim to the user — it already explains what
was restored, what was undone, and what was kept (and why).

Common outcomes:

- "Review X restored. Status: dismissed → pending. Learned rule Y removed." — happy path.
- "Review X restored. ... Learned rule Y kept — also referenced by other dismissals." — shared rule, untouched.
- "Review X restored. ... No learned rule was created by this dismissal." — low-confidence reflection produced no rule.
- "Review X wasn't dismissed (status: pending). No change." — idempotent no-op.
- "siltpoke-undismiss: review X not found." — unknown id; exit code 1.

For JSON output (scripting): `bun ... undismiss.ts <id> --json`.

Related: `/siltpoke-dismiss <id> "<reason>"` to dismiss again.
